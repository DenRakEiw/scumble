## 3. The Realism Pass: shared ground for R1-R5

### 3.1 What the pack offers and refuses (read only, pack HEAD 796ed59)

- **Nodes** (V3 API, category image/upscaling): `DLSS5Settings` (output type `DLSS5_SETTINGS`), `DLSS5EnhanceImages`
  (`images` IMAGE, `settings`, `verify_neural_rendering` BOOLEAN default true; one IMAGE output). A third node,
  `DLSS5EnhanceVideoFile`, is not used.
- **`DLSS5Settings` inputs** (`nodes/settings_node.py:30-157`, ranges in `dlss5/settings.py`): `upscaling_mode`
  (`"1x (DLAA / native)"`, `"1.5x (Quality)"`, `"1.724x (Balanced)"`, `"2x (Performance)"`, `"3x (Ultra Performance)"`),
  `nr_preset` (Default, Preset #1-#3; no measured effect), `nr_style` (Default, Natural, Cinematic), `nr_intensity`
  (0-2; above 1 does nothing more), `local_tone_strength` (0-2, 1.0), `local_structure_strength` (0-2, 1.5),
  `skin_structure_strength` (-1 to 2, 2.0; only while `automatic_mask` is on), `automatic_mask` (true),
  `dlss_model_preset` (Default, J, K, L, M; default M), and the advanced `motion` (auto / optical_flow / none),
  `scene_change_threshold` (0.01-1, 0.24), `warmup_frames` (0-16, 0), `runtime_dir` (empty: config.json, then
  `DLSS5_RUNTIME_DIR`, then the pack's `runtime/`). `DlssOptions.create` raises a ValueError on any bad value.
- **Sizes** (`dlss5/settings.py:44-105`): the output is the input times the factor, rounded to even numbers (`_even`:
  641 × 481 comes back 642 × 482). The output may be at most 7680 on the long edge and 4320 on the short edge. The
  render size must be at least 64 px a side (`session.py:151-155`). `fit_frame` (`dlss5/imaging.py:22-39`) fits a
  picture whose size differs from the negotiated one, centred and without distortion: one odd side gives a 1-px black
  column or row, two odd sides a resample by a fraction of a pixel. Scumble pads to even sizes first (R2a), so neither
  happens.
- **Batches are a time sequence.** `motion` auto turns optical flow on for more than one frame (`wants_motion`). A
  single picture with `auto` is the same as `none`. Unrelated pictures must go one at a time: always one picture
  (`ImageFromBatch` length 1) before `DLSS5EnhanceImages`.
- **Alpha:** a 4-channel IMAGE keeps its alpha. `LoadImage` and `InpaintCanvasLoadRef` give 3 channels, so alpha is
  put back in the app.
- **Timing (pack README):** the worker starts once per prompt (about 4 s on a 5090), then about 10 frames/s at 720p.
- **The nodes load without the runtime.** `/object_info` cannot tell whether the runtime is there. A missing runtime
  shows only when a run fails.
- **Windows only** (D3D12, ReShade, the RenoDX add-on). The GPU rule (`dlss5/diagnostics.py:105-143`): nvidia-smi's
  first line whose name holds "RTX"; the generation is `/RTX\s+(\d{2})/` on the name; under 30 is refused; RTX 30 also
  needs a hash-checked "experimental Ampere pair" of runtime files.

### 3.4 The pack's failures, as the user reads them (`realism.hint(message, nodeType)`, R1)

The pack raises RuntimeError. It arrives as `execution_error` with `node_type` `DLSS5EnhanceImages` (or `DLSS5Settings`)
and `exception_message`. Matching is on stable substrings of the pack's text (fixtures copied once into
`tools/refs/dlss5/messages.json`).

| Pack message contains | The user sees |
| --- | --- |
| `No DLSS 5 runtime was found` | "{LABEL}: the DLSS 5 runtime is not installed on your ComfyUI. Install it there with the pack's install_runtime.py (Help › Manual › {LABEL})." |
| `is incomplete. Missing` | "{LABEL}: the DLSS 5 runtime on your ComfyUI is incomplete (missing: <files>). Install it again (Help › Manual › {LABEL})." |
| `nvidia-smi is unavailable` | "{LABEL}: your ComfyUI's machine shows no NVIDIA driver. It needs Windows, an RTX 30, 40 or 50 card and a current driver." |

### 3.5 Scumble's own refusals and waits

| Case | When | The user sees |
| --- | --- | --- |
| Too small | before queueing | "{LABEL} needs at least 64 px a side; this is <W × H>." |
| Too large | before queueing | "{LABEL} takes at most 7680 × 4320 (long × short side); this is <W × H>." (The Realism Pass Upscale scales down instead, §1.) |
| Queue busy | while waiting | Status: "{LABEL} waits for your ComfyUI (<N> jobs ahead) ..." (read from `/queue` every 2 s). The pass queues at the front (`queuePrompt(-1)`, as the helpers do); it never interrupts a running job. |
| Disconnected while waiting | the status leaves `connected` | "{LABEL}: the connection to your ComfyUI was lost." plus the route's ending. |
| Timeout | 300 s by default (`settings.realism.timeout`) | "{LABEL}: no answer from your ComfyUI within 300 s; its job was taken off the queue." plus the route's ending. |
| Cancel (the title row's Cancel) | any time | "{LABEL} cancelled." plus the route's ending. Only Scumble's own prompt is removed: `POST /queue {delete:[id]}`, then `POST /interrupt {prompt_id:id}` (ComfyUI interrupts only when that id is the running one, `server.py:1168-1192`). Never a global interrupt. |

## 6. Traps from CLAUDE.md that apply

- **The user's ComfyUI (8188) is a production machine.** Every gate runs `--offline` (`--no-comfy`); a fresh gate
  profile otherwise connects to 8188 and forwards every upload. No `smoke`. Live looks only on the user's word, `/queue`
  first, own prompts deleted, never a restart, never a global interrupt.
- **The editor is shared with the node.** `build_node.py --check` fails when an editor module calls a host member the
  node's `js/host.js` lacks. New code goes into `host.js`, `shell.js`, `commands.js` and app-only modules
  (`realism.js`, `comfyprompt.js`, not in `FILES`). `GEN_DEFAULTS` and `inpaint_modal.js` stay untouched. Run
  `nodecopy` only if a shared file changes after all.
- **The renderer keeps its own copy of the settings.** `settings.realism` changes go through the shell's path, and a
  gate that changes it or the selected recipe puts both back (`selectRecipe`), or a later gate fails on the
  difference.
- **`settings.get()` merges only the top level and `set()` writes the whole object** (`settings.js:69-84`, the
  `embedRecipe` trap): `settings.realism` is read filled per key (`fillValues`) and always written whole.
- **contextBridge objects are read-only** from the page (memory `scumble-phase4-plugins`): a gate cannot stub
  `window.scumble.comfy.ensure`; it stubs the host member around it (`host.ensureRefs`, R2a), and the real ensure
  throws "ComfyUI is not connected" under `--no-comfy`.
- **An older ComfyUI may ignore `prompt_id` in `/interrupt`** and interrupt whatever runs: Scumble interrupts only
  after `GET /queue` shows its own id running (R2a).
- **Hidden windows:** `requestAnimationFrame` does not fire and `img.decode()` never resolves. Scripted waits use
  `setTimeout`; image loads (`bytesToImage`) wait for `onload`.
- **`drawImage` with `copy` and smoothing on changes pixels by up to 2 levels.** The even padding, the crop back and the
  alpha put-back use `source-over` with smoothing off.
- **The acceleration latch:** many `getImageData` calls make every new canvas software. One readback per picture.
- **Tile bytes are views into a SharedArrayBuffer**: the whole-picture read goes through `encodeComposite` /
  `flattenToCanvas`, never raw tiles; `makeCanvas` throws above Chromium's limits (the pass refuses above 7680 × 4320 first).
- **electron-updater installs a downloaded update on every normal quit** (`autoInstallOnAppQuit`): the portable copy
  turns it off before any check, and never downloads.
- **`--user-data-dir` wins** over the Store and the marker, so no existing gate reaches the portable path: the `portable`
  gate starts its own copies without it. Each test run otherwise has its own `--user-data-dir` (memory
  `scumble-benchmark-hygiene`: the default profile once lost the user's document).
- **Only one instance per data folder** (single-instance lock and named pipe, both keyed by `userData`): stop the dev
  instance before starting `dist/win-unpacked/Scumble.exe`; a test that closes the app sends WM_CLOSE.
- **A test that starts the exe from Python needs its absolute path** (WinError 2).
- **`npm run dist:store` rewrites `dist/win-unpacked` without `app-update.yml`**: the zip is built after `npm run dist`
  and before `dist:store`; `portable_zip.js` refuses otherwise. `makeappx.exe` from electron-builder's cache under
  `%LOCALAPPDATA%` fails from Node and PowerShell; Git Bash runs it.
- **PowerShell `Set-Content` writes a BOM** that electron-builder refuses in `package.json`.
- **The Write tool turns `\u0080` escapes into characters**; check written files with `grep -nP "[^\x00-\x7F]"` where
  escapes matter. Heredocs break on apostrophes and run backticks: scripts are written with the Write tool.
- **`editor_test.py` and the gate steps hold JS in Python strings**: `\\n`, not `\n`.
- **Reusing one commit message file gives the next commit the old message.** Commits as DenRakEiw, no trailer.
- **Re-run a failing gate before believing it** when its step is a listed flake (`docs/TESTING.md`).
- **The website is committed with its own identity**, no `Co-Authored-By` trailer (a second author blocks the Hobby
  deploy).
- **No other product's name as a feature's model** in the CHANGELOG, the manual, the README or the post. NVIDIA, DLSS
  5, RTX Video Super Resolution and the community pack are named only where the text is about running them.
- **No ComfyUI install path is assumed** and Scumble keeps working without any ComfyUI (item 35's rules): everything
  goes through the URL, `/system_stats` and `/object_info`.
