### A1: item 32, a dialog when an update is ready (about half a day)

**Built 2026-10-02 night** (CHANGELOG Unreleased). Changes against the plan below, found while building:
- electron-updater installs a downloaded update **when the app quits** (`autoInstallOnAppQuit`), so *Skip* had to
  reach main: `updater.js` `setSkip` / `_applySkip` turn `autoInstallOnAppQuit` off while the offered version is the
  skipped one (6.8.9 reads the switch when a download ends and again in its quit handler), main reads
  `settings.updates.skip` at the start and on every `settings:set` with `updates`, and `app:relaunch` (the tiles
  restart) no longer installs a skipped version. *Later* is honest about it: it installs on close.
- `announced` lives in main's memory (`updater.announce`, IPC `update:announced`), not in the settings: once per start
  (a window reloaded after a crash does not ask again), and the next start asks again; normally the next start is the
  new version anyway (installed on close).
- The detail lists each release-note bullet's **bold lead** (`releaseHeadlines`, the feed's `<li><strong>`), at most
  eight and "... and N more"; the cut notes are only the fallback for notes without leads.
- The question also waits for any modal `<dialog>`, the restore at start, `userBusy` of every editor and 3 s after
  the last key / click / wheel; `installUpdate()` asks before ending a run, the assistant's turn or an agent's session,
  and the title-row button and Settings' Install go through it too.
- Tests: `tools/updater_test.js` (plain Node, the 0.1.37 feed as `tools/refs/updates/release_0_1_37.html`), the
  platform gate step `the_update_question_asks_once`, a `tools/restart_test.js` row.
- A review workflow (four dimensions, every finding checked by a skeptic; 16 findings, 12 held) changed: one line per
  **top-level** bullet (a lead, else the first sentence; sub-bullets belong to theirs), `fullChangelog` on (every
  release since the installed one) and the notes' cap 4,000 -> 30,000 characters with "…" (0.1.37 alone is 8,300; the
  manual's "the whole release notes" is true now), a skipped download is checked again, `manual` is never taken back
  by the start check and is set by a check during a download, the quit handler is added when a skip is taken back, the
  focus opens on *Later* (`dialogs.ask` `focusId`: a key typed into the question never restarts), a local ComfyUI
  render counts as working (`_localRuns`), the question waits for the assistant's card (`assistantActivity().asking`),
  the assistant's `busy` survives a window reload during a turn (`refresh` after `replay`), and the gate step's
  negative cases cannot hang it. Not changed (outside the item): README's line that the .deb does not update itself
  (electron-builder 26 ships the .deb with `app-update.yml`, so electron-updater's DebUpdater would update it through
  pkexec; never run on Linux).

Today (read 2026-10-02): `main.js` checks GitHub 8 s after the start (packaged, not headless, not in agent mode,
`settings.updates.check !== false`; `updater.js` states dev / store / idle / checking / latest / downloading /
downloaded / error, `autoDownload` on), the renderer's `renderUpdate(s)` (`renderer/shell.js` ~2011) shows only the
title-row button `#shell-update` ("Update to X") and, in *Settings > Updates*, the note, the release notes and Install.
`update:install` (main) saves every window first (`quitGuard.run(flushAll)`) and runs the installer.

Build:
- In `shell.js`, when a status arrives with `state === "downloaded"`, `!s.manual` (a manual check shows its answer in
  Settings already), and the version is neither announced nor skipped: one dialog through `renderer/dialogs.js`
  `ask({ title, message, detail, buttons, defaultId, cancelId })`: title "Scumble <version> is ready", the message
  one line (installed: current -> new), the detail the release notes as text (`s.notes`, cut at about 1,500
  characters with "..., the rest in Settings > Updates"), buttons *Restart and update* (default), *Later* (cancel),
  *Skip this version*.
- *Restart and update*: when a document is busy (a run in flight: `host.editors().some((e) => e.busy)` or what
  `list_documents` reads as `busy`) or the assistant works, first `confirm("A run is still going ...")`; then
  `window.scumble.updates.install()` (it saves first). *Later*: nothing now, asked again at the next start; the title
  button stays. *Skip this version*: `settings.updates.skip = version` (no dialog for that version; the title button
  and Settings still offer it).
- `settings.updates.announced = version` after the dialog closes either way, so one start shows it once (a second
  window of the same start does not ask again). Defaults in `electron/main/settings.js` (`updates: { check: true }`
  gets nothing new: absent means none).
- Not while another dialog is open (`dialogs.openCount() > 0`): wait until it closes. Never in the Store copy or dev
  (their states never reach "downloaded").
- Docs: CHANGELOG Unreleased, `docs/MANUAL.md` (the updates paragraph; `node tools/manual_test.js`).
- Test (normal tier): a gate step that feeds `renderUpdate` (or the new `announceUpdate`) a fake status and reads the
  dialog: shown once, *Skip* writes `updates.skip`, a skipped or announced version shows none, `manual: true` shows
  none. Find the gate that already covers the updates UI (`grep -n "updateBar\|renderUpdate" tools/*.py`); else
  `commands_test.py`. One look in the app.

### A2: three small leftovers (a few hours)

**Built 2026-10-02 night** (CHANGELOG Unreleased, three lines). 1: `host.js` `answeredSeed(res)` puts the adapter's
`seed` into the result (`addResults` takes `r.seed` when given; a local result keeps the editor's), so `generate`
answers `seed: null` for FLUX 3 and the history row says "api · no seed sent"; the loopback's `options.no_seed` stands
in (commands gate step `generate_reports_the_seed_the_model_got`). Only adapters that already report no seed change
(bfl's FLUX 3, WaveSpeed without `seed` in `accepts`); the others report `req.seed` as before, sent or not (OpenAI,
Gemini, ToAPIs and ModelArk take none: not touched). 2: `idWords` takes the last two words of the first phrase; an
-ing word ends the phrase once it has a word, except a short list of -ing nouns (ring, building, painting ...);
`tools/boxes_test.js` has nine new cases. 3: the request carries `cropAspect` (stitch's `info.aspect`), `flux3.js`
sends it when it is one of the 15 presets and within 8 % of the emitted size (`tools/flux3_test.js`, three cases).

1. **`generate` reports a seed FLUX 3 never got.** `renderer/commands.js` ~815 returns `seed: h.seed` (the editor's
   seed). A provider run whose adapter sends none (FLUX 3: `bfl.js` reports no seed; WaveSpeed's Ideogram 4.5 sends
   none either) should answer `seed: null`. Trace where `h.seed` is set (`host.runProvider` / the provider answer's
   `info`), carry "no seed sent" from the adapter, and say it in the status line only if it already names a seed.
   Test: `tools/flux3_test.js` / the `generate` gate's loopback, whichever reaches the field.
2. **Box names skip the adjectives.** `renderer/editor/boxes.js` `idWords` takes the first two telling words, so "a
   small black cat sitting in the grass" -> `small_black`, "the white wall clock" -> `white_wall` (seen live). Better:
   the first phrase of telling words, ended by a stop word or a word ending in "ing" ("sitting", "leaning"), and of
   it the **last two** words: `black_cat`, `wall_clock`, `red_scarf`, "make the tiger pink" -> `tiger_pink` (as now).
   Only ids made from now on change (an id once made stays). Test: `tools/boxes_test.js` (the idWords cases), the
   `boxes` gate's S3e step if it pins an id.
3. **planCrop's aspect does not reach the FLUX 3 adapter.** `stitch.js` `planFrame` returns `aspect: p.info.aspect`
   (the preset the crop was widened to); `flux3.js` picks the preset nearest the emitted crop within 3 % and sends
   "auto" otherwise, so a crop whose 16 px rounding lands past 3 % goes as "auto" (works, but the answer is then not
   stretched onto a known preset). Pass the planned preset with the edit request (`req.cropAspect` or in the crop
   info) and let `sizeOf` prefer it when it is one of the 15 presets. Test: `tools/flux3_test.js` (a crop 4 % off its
   planned preset sends the preset).
