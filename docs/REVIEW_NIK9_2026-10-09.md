## Smaller

- **`belowHistogram` and `belowSample` return `null` for filters with custom `wholeStats`**
  (`renderer/editor/inpaint_canvas.js:13854, :13862`). `belowHistogram` reads `st.hist` and `belowSample` reads `st.bytes`
  from `belowStats(layer)`. When a filter specifies custom `wholeStats(small, size, ctx)`, `belowStats` stores that
  function's return value in `layer._bstats`. If the returned object has no `hist` or `bytes` (as will be the case for
  `haze` and `dehaze` in R2-S12/S14), a Luma or Color limit on that filter layer renders no histogram in its range bar.
  The range bar handles `null` gracefully without throwing, but if a histogram is desired for limits on such layers,
  `belowHistogram` / `belowSample` should fall back to `colourStats(small)`.
- **`mapsOf` only accepts `def.maps` as a function** (`renderer/editor/inpaint_canvas.js:12204`). `registerFilter` in
  `plugins.js:309` wraps array declarations in `() => def.maps`, but built-in filters defined directly in `FILTERS`
  (in `inpaint_filters.js`) without going through `registerFilter` would be ignored if declared as `maps: ["depth"]`
  instead of `maps: () => ["depth"]`. Supporting `Array.isArray(def.maps)` in `mapsOf` avoids traps in R2-S12.
- **`tools/plugin_api4_test.js` has 9 unused variables triggering linter warnings** (`tools/plugin_api4_test.js:50, 52, 58, 66, 116, 208, 214, 218, 222`).
  `pluginHost`, `applyParams`, `testEntry`, `origFilters`, `lastStatsCtx`, `st2`, `st3`, `stMap1`, `stMap2` are assigned
  but never read.
- **`_undoPending.params` shallow copy** (`renderer/editor/inpaint_canvas.js:12226`). `cancelFilterParams` restores
  `layer.params = { ...(layer._undoPending.params || {}) }`. This works today because parameter modifications during
  preview assign fresh objects for compound params (`limit` in `:17572`, `curve` in `inpaint_curves.js:130`). If a future
  control ever mutates a nested parameter object in-place, shallow copy will not revert it.

## Smaller

- **Unused `gaussRadii` import in `tools/edges_test.js:38`**:
  `gaussRadii` is destructured from `edgesMod` but never asserted or invoked in `edges_test.js`, producing an ESLint `no-unused-vars` warning. An explicit assertion on `gaussRadii(2.0)` (e.g. verifying it returns 3 radii approximating Gaussian blur) would both test the export and eliminate the warning.
- **Array allocation in `snapRgb` (`renderer/editor/inpaint_edges.js:55`)**:
  `snapRgb` returns a fresh 3-element `[r, g, b]` array on every invocation. In `snapField`, the 4x4 bilateral kernel calls `snapRgb` 16 times per sample point (16 array allocations per point). For interactive point queries (hover or `sample_depth`) this is unnoticeable, but if `snapField` is ever used in a CPU fallback loop across full images, inlining or reading directly from the `Uint8Array` guide data will eliminate millions of allocations.
- **Overlap window ramp with dropped neighbors in `fuseTiles` (`renderer/editor/inpaint_edges.js:456-477`)**:
  `oxLeft, oxRight, oyTop, oyBot` are computed by inspecting all tile boxes without checking whether adjacent tiles were dropped (`dropped === true`). In the interior of a surviving tile adjacent to a dropped tile, `sumWHi / sumW` normalizes to `Hi` as expected, but right at the boundary where `sumW` drops below `1e-6`, the high-frequency contribution steps to 0. When R2-S7 implements the full detail pass, it may be beneficial to smoothly feather `Hi` towards 0 at transitions into dropped tiles.
- **JSDoc type signature for `map` in `snapField` (`renderer/editor/inpaint_edges.js:62`)**:
  JSDoc declares `@param {{ data: Uint16Array, w: number, h: number } | Uint16Array} map`. However, line 77 reads `map.w` and `map.h` directly (`const mw = map.w, mh = map.h;`), which would yield `undefined` if a bare `Uint16Array` were passed. All current callers pass `{ data, w, h }` matching the module convention, but the JSDoc type should strictly reflect `{ data: Uint16Array, w: number, h: number }`.
