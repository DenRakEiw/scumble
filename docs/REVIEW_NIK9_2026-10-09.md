## Must fix before R2-S2 builds on it

1. **`filterKey` throws `TypeError: this.mapsOf is not a function` in unit tests** (`renderer/editor/inpaint_canvas.js:13706`,
   `tools/limit_test.js:133`, `tools/maps_test.js:473`). `filterKey` was changed to call `this.mapsOf(layer).length > 0`.
   Real `InpaintEditor` instances have `mapsOf` on `InpaintEditor.prototype`, but the Node unit test harnesses
   `dummyEditor` in `tools/limit_test.js:108-112` and `editor` in `tools/maps_test.js:382-410` mock the editor by borrowing
   `filterKey: InpaintEditor.prototype.filterKey` without `mapsOf`. As a result, running `node tools/limit_test.js` or
   `node tools/maps_test.js` crashes immediately with `TypeError: this.mapsOf is not a function`.
   Fix:
   - In `renderer/editor/inpaint_canvas.js:13706`, guard the call defensively:
     `if ((typeof this.mapsOf === "function" ? this.mapsOf(layer).length > 0 : (layer.params?.limit?.source === "depth" || layer.params?.limit?.source === "map")))`
   - In `tools/limit_test.js:111` and `tools/maps_test.js:406`, add `mapsOf: InpaintEditor.prototype.mapsOf`.

## Smaller

- **`belowHistogram` and `belowSample` return `null` for filters with custom `wholeStats`**
  (`renderer/editor/inpaint_canvas.js:13854, :13862`). `belowHistogram` reads `st.hist` and `belowSample` reads `st.bytes`
  from `belowStats(layer)`. When a filter specifies custom `wholeStats(small, size, ctx)`, `belowStats` stores that
  function's return value in `layer._bstats`. If the returned object has no `hist` or `bytes` (as will be the case for
  `haze` and `dehaze` in R2-S12/S14), a Luma or Color limit on that filter layer renders no histogram in its range bar.
  The range bar handles `null` gracefully without throwing, but if a histogram is desired for limits on such layers,
  `belowHistogram` / `belowSample` should fall back to `colourStats(small)`.
- **`mapsOf` only accepts `def.maps` as a function** (`renderer/editor/inpaint_canvas.js:12204`). `registerFilter` in
  `plugins.js:309` wraps array declarations in `() => def.maps`, but built-in filters defined directly in `FILTERS`
  (in `inpaint_filters.js`) without going through `registerFilter` would be ignored if declared as `maps: ["depth"]`
  instead of `maps: () => ["depth"]`. Supporting `Array.isArray(def.maps)` in `mapsOf` avoids traps in R2-S12.
- **`tools/plugin_api4_test.js` has 9 unused variables triggering linter warnings** (`tools/plugin_api4_test.js:50, 52, 58, 66, 116, 208, 214, 218, 222`).
  `pluginHost`, `applyParams`, `testEntry`, `origFilters`, `lastStatsCtx`, `st2`, `st3`, `stMap1`, `stMap2` are assigned
  but never read.
- **`_undoPending.params` shallow copy** (`renderer/editor/inpaint_canvas.js:12226`). `cancelFilterParams` restores
  `layer.params = { ...(layer._undoPending.params || {}) }`. This works today because parameter modifications during
  preview assign fresh objects for compound params (`limit` in `:17572`, `curve` in `inpaint_curves.js:130`). If a future
  control ever mutates a nested parameter object in-place, shallow copy will not revert it.
