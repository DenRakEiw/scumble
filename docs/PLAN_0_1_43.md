## 3. Nano Banana 2.1: what is known (read 2026-10-07, not run)

- **Google, generateContent.** Model id `gemini-nano-banana-2.1`, stable, "latest update October 2026". The legacy
  generateContent page (https://ai.google.dev/gemini-api/docs/generate-content/image-generation) calls
  `POST .../v1/models/gemini-nano-banana-2.1:generateContent` (**v1**; the adapter uses `v1beta`, and no page says
  whether v1beta takes the model). `generationConfig.imageConfig { aspectRatio, imageSize }` is still in the API
  reference (https://ai.google.dev/api/generate-content); the page's own examples moved to
  `generationConfig.responseFormat.image`. ComfyUI's 2.1 node sends `imageConfig` and `thinkingConfig.thinkingLevel`
  (through Vertex). The main image page (`/docs/image-generation`) shows only the new Interactions API now.
- **Sizes:** `1K` (default), `2K`, `4K`; **no 512 / 0.5K** ("not supported on Gemini Nano Banana 2.1").
- **Ratios:** 1:1, 1:4, 1:8, 2:3, 3:2, 3:4, 4:1, 4:3, 4:5, 5:4, 8:1, 9:16, 16:9, 21:9 at every size (16:9 is 1376 x 768
  / 2752 x 1536 / 5504 x 3072; 8:1 is 3072 x 384 / 6144 x 768 / 12288 x 1536). Without an aspect the answer takes the
  input picture's shape.
- **Thinking:** `thinkingConfig.thinkingLevel` `minimal` / `medium` (default) / `high`; cannot be turned off, billed
  either way. NB2 has only minimal (default) and high. **Thought images**: the model makes up to two interim pictures;
  they come back as parts with `"thought": true` (with `includeThoughts`; ComfyUI's `get_image_from_response` skips
  them in any case). **`gemini.js` takes the first part with `inlineData`** (`electron/main/providers/gemini.js:95`),
  so a draft could land as the result; `comfyrouter.js:440` already takes the last part that is not `thought`.
- **Pictures in:** 14 (4 characters, 10 objects). No mask input on any host. SynthID on every picture.
- **Price per picture (Google, standard):** 1K $0.0336, 2K $0.0504, 4K $0.113 (NB2: $0.067 / $0.101 / $0.151); input
  $1.50 per 1M tokens (NB2 $0.50). https://ai.google.dev/gemini-api/docs/pricing
- **Hosts** (each with the URL the agent read):
  - fal: `fal-ai/nano-banana-2.1/edit` and `fal-ai/nano-banana-2.1`; `image_urls`, `resolution` 1K/2K/4K,
    `aspect_ratio` auto + the 14, `thinking_level` minimal/medium/high (default medium), `safety_tolerance`; no cap in
    the schema (https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=fal-ai/nano-banana-2.1/edit).
  - Replicate: `google/nano-banana-2.1`; `image_input` (up to 14), `aspect_ratio` (the 14 + `match_input_image`),
    `resolution` 1K/2K/4K, `output_format` jpg/png; no thinking (https://replicate.com/google/nano-banana-2.1/llms.txt).
  - WaveSpeed: `google/nano-banana-2.1/edit`; `images` (max 14), `aspect_ratio` (the 14), `resolution` "1k"/"2k"/"4k"
    lowercase; no thinking (https://wavespeed.ai/models/google/nano-banana-2.1/edit).
  - OpenRouter: `google/gemini-nano-banana-2.1`, context 65,536; `reasoning` / `reasoning_effort` listed, whether they
    set the thinking level not checked (https://openrouter.ai/api/v1/models).
  - Comfy Cloud: the node `GeminiNanoBanana2V2` (NB2's node, `comfycloud.js:66-68`) with the model option "Gemini Nano
    Banana 2.1"; `model.resolution` 1K/2K/4K, `model.thinking_level` MINIMAL/MEDIUM/HIGH (default MEDIUM),
    `model.images.image_1..14`; ComfyUI PR #16822 (2026-10-06), seen in the live catalog. `comfycloud.js:68` sets
    `thinking_level` MINIMAL for every model of the node today.
  - Comfy Router: `vertexai/gemini-nano-banana-2.1`, Vertex body, `imageSize` 1K/2K/4K, `thinkingConfig.thinkingLevel`
    (https://docs.comfy.org/router-schemas/vertexai/gemini-nano-banana-2.1.json).
  - ToAPIs: `gemini-nano-banana-2.1` and `-vip`, no `-official` channel; fields not read (https://toapis.com/models).
  - Oxen: **not listed** (checked against https://hub.oxen.ai/api/ai/models): no variant.

### B1: agent and MCP errors (normal)

- **`cutout_layer` reports a failure after a successful in-app cutout** (`renderer/commands.js:1615-1617`):
  `cutoutLayer` (`renderer/editor/inpaint_canvas.js:12650`) finishes the in-app path inside the call
  (`:12661`), so `cutoutPending` is false on success too. Fix: `cutoutLayer` returns `"started"` (a ComfyUI run under
  way), `"done"` (in-app finished) or `false` (did not start, with `status` set); the command throws only on `false`,
  waits only on `"started"`. The panel's button (`:15190`) ignores the value.
- **Filter params sent as a JSON string are refused** (`checkParams`, `renderer/commands.js:2052-2054`; callers
  `:1674`, `:1693`): parse a string that holds a JSON object before the check; anything else keeps the refusal. Also
  look at how `P.obj` reaches the MCP schema (whether `params` is declared `type: object` for the adapters).
- Test: a `commands` gate step each (the cutout with an in-app model stub or the model present; `add_filter` with
  `params: "{\"color\":\"#ff2d2d\"}"`), tiles backend.

**As built (2026-10-07):** as planned. `cutoutLayer` answers `"started"` / `"done"` / `false` (`applyCutoutImage`
answers whether it applied); `cutout_layer` throws only on `false`, waits only on `"started"`, and after the wait
also refuses "Could not apply". `checkParams` parses a JSON-object string. The MCP schema already says `type: object`
(`P.obj`); the refusal came from `checkParams` alone. One `commands` step, `cutout_and_string_params` (a stub in-app
model through `host.cutoutBackends` / `host.cutoutInApp`, put back afterwards): PASS on tiles; on the old code it fails
with the reported symptom. eslint (no new warnings) and tsc clean.
