K11 measurement summary (2026-11-08)
====================================

Scope (docs/PLAN_WASM_BUILD.md §4.3 K11, §7 K5, Stop 3):
- `mask_invert` in `crates/px/src/sel.rs` (SIMD128 `i32x4_sub(u32x4_splat(255), u32x4_shr(v, 24))` + scalar tail +
  `rest_of_row` extent scan), exported from `crates/px/src/lib.rs` (ABI 29), wrapped in `renderer/editor/px/px.js`
  (`Px.maskInvert`), JS twin in `renderer/editor/px/kernels_js.js` (`maskInvert`), routed as `"kernel"` in
  `renderer/editor/px/kernels.js` (`maskInvert`, default `"rust"`).
- `TileMaskPixels.prototype.invert` in `renderer/editor/inpaint_tiles.js` calls `maskInvert` on every existing tile
  (when `LITTLE`), dropping tiles whose inverted extent is `null` without calling `writable` on the Rust route and
  storing `t.ext = ext; t.extVersion = t.version;` on every kept tile (both the kernel path and the `!had` fill path),
  so `bounds()` after `invert()` does not scan the tiles again.
- Deferred `writable(tx, ty, create = true, whole = false)` copy (`renderer/editor/inpaint_tiles.js` and
  `allocTileBytes(owner, zero = true)` in `renderer/editor/inpaint_arena.js`): when `whole` is true (the caller
  overwrites all `SLOT_BYTES = 262,144` bytes in the same synchronous step via wasm `_out` or a full-tile `w.fill`),
  `writable` skips `c.data.set(t.data)` on frozen tiles (`t.frozen > 0`) and `allocTileBytes` skips `bytes.fill(0)` on
  reused arena slots. Used by both `TileMaskPixels.invert` and `TileMaskPixels.combine` (`selCombine` and full-tile
  `SEL_FULL` fills).
