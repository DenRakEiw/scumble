K16 measurement summary (2026-11-09)
====================================

Behaviour changes on damaged or odd files:
- An LZW strip or tile with a damaged code past `need`, inside the blob piece that completes `need`, was refused and now opens (whether trailing LZW damage refused a file before depended on where the pieces broke, as later pieces were already ignored because `StripRows` and `TileRows` closed at `need`; `packBitsDecoder` has no refusal path so PackBits behaves as before, stopping at `need` with the same pixels).
- An LZW strip or tile whose stream yields a 1-byte first chunk `[b]` followed by a chunk of two or more bytes starting with the same byte `b` now keeps that first byte and checks the second byte for old-style LZW, instead of dropping the first byte and testing the third byte.

Scope (docs/PLAN_WASM_BUILD.md §4.6 K16 + brief overrides at 3fd8bda7):
- `crates/px/src/tiff.rs` (created) and `crates/px/src/lib.rs` (ABI bumped 36 -> 37):
  - `tiff_unpack(compression: u32, src: *const u8, len: usize, out: *mut u8, need: usize) -> isize`
  - Unpacks one TIFF strip or tile of `need` bytes for `compression` `1` (none), `5` (LZW, 9..12-bit MSB-first codes, 24 KB tables on the stack: `prefix: [u16; 4096]`, `suffix: [u8; 4096]`, `first: [u8; 4096]`, `len: [u16; 4096]`), and `32773` (PackBits).
  - Deflate (`8` / `32946`) stays on native `DecompressionStream` (Stop 2 went to native inflate; `tiff_unpack` returns `-1` for unsupported compression).
  - Panic-free by reading (table indices masked to `0xFFF`, `next` capped at `4096`, `width` in `9..=12`, all slices bounds-checked) and backed by the fuzz and prefix-sweep runs below; stops as soon as `need` bytes are written (`return need as isize`) and returns negative error codes on corrupt or truncated input (`-1` bad args/compression, `-2` truncated before `need` bytes, `-3` old-style LZW, `-4` LZW code before first literal after clear, `-5` LZW code beyond table).
- `renderer/editor/inpaint_tiff.js`:
  - Fixed the 1-byte first-piece bug in `lzwDecoder(need = Infinity)`: `head` (`-1` initially) stores `chunk[0]` only when the first non-empty `push()` chunk has `chunk.length < 2`; on the next chunk `head >= 0` uses `head` as the first byte and `chunk[0]` as the second byte (seeding `acc = head; nbits = 8`), instead of testing `head === chunk[0]`.
  - Added `need` stopping to `packBitsDecoder(need = Infinity)`, `lzwDecoder(need = Infinity)`, and `unpacked(src, off, count, compression, name, need = Infinity)`, passing `this.need` from `StripRows.open` and `want` from `TileRows.tile`.
  - Added `unpackStrip(compression, src, need, out = null, name = "strip")` and `TIFF_JS = Object.freeze({ unpackStrip })`, validating `ArrayBuffer.isView(src)` (and `ArrayBuffer.isView(out)` when `out != null`).
- `renderer/editor/px/px.js`, `renderer/editor/px/kernels_js.js`, `renderer/editor/px/kernels.js`:
  - Bumped `PX_ABI = 37`, added `Px.prototype.tiffUnpack` (validating `ArrayBuffer.isView(src)` and `ArrayBuffer.isView(out)`) and `tiffUnpackError(code, name)`, re-exported `unpackStrip` / `TIFF_JS` / `tiffUnpack` with trap recovery and `releaseIfLarge()`.
  - K16 is §1.4's kernel tier (its app call site is K17's `readTiffBand`; no route entry, app gate step, `pxjobs`, or 15k rows at K16 per brief override).
