1. What the copy of `lines` into wasm memory (`copyIn`) costs
-------------------------------------------------------------
Because `DecompressionStream("deflate-raw")` delivers the inflated `lines` as a JS `Uint8Array`, `px.pngPartDecode`
copies `lines` (`rows * (1 + 4 * w)` bytes) into wasm memory before `png_part_decode` runs:
- On an `8.34 MB` part of a `15,000`-wide RGBA8 layer (`15,000 x 139`, `8,340,139` bytes of `lines`, `8,340,000` bytes
  of `out`; note that with tile-row alignment `align = 256`, `forParts(15000, 10000)` splits a `15,000 x 10,000` layer
  into **79** parts of `127` rows = `7.62 MB` each, vs `72` parts of `139` rows before tile-row alignment):
  - **Electron 44.2.0 (V8 15.2)**: **`0.43 - 0.47 ms`** per `8.34 MB` part (`0.052 - 0.056 ms/MB`, `17.7 - 19.4 GB/s`),
    which is **`3.2% - 4.2%`** of the `10.67 - 13.35 ms` single-pass `pngPartDecode` call (`0.43 / 13.31 = 3.23%`).
  - **Node 24.18.0 (V8 13.6)**: **`0.43 - 0.53 ms`** per `8.34 MB` part (`0.052 - 0.064 ms/MB`, `15.7 - 19.4 GB/s`),
    which is **`3.1% - 4.4%`** of the `11.69 - 14.34 ms` single-pass `pngPartDecode` call.
  - When a part's `prev` is not yet available (`prev == null` and `firstFilter >= 2`, `needsPrev: true`), `lines` is
    copied in twice: once during `png_part_decode` (for the whole-line check, filter check, and Adler-32: `3.08 ms`
    total in Electron V8) and once during `png_part_finish` (`2 x copyIn = 0.91 ms` in Electron V8, `0.82 ms` in Node
    V8; `5.0%` of the `18.04 ms` `decode + finish` total). Because K6's filter census showed that **99% of rows in
    files written by Scumble use Paeth or Average (`firstFilter >= 3`)**, the **two-copy `needsPrev` + `png_part_finish`
    path is the likely case** for parallel out-of-order part decoding of Scumble's own files (for all non-first parts).
  - **Inferred pool-wide figures for a `15,000 x 10,000` layer (79 parts, `600.01 MB` of `lines`, inferred from
    single-threaded laps on a warm arena, not measured on 8 concurrent workers)**:
    - Single-copy path (`prev` known or `firstFilter <= 1`): inferred sum **`~31.2 - 34.1 ms`** across the 79 parts
      (**`~3.9 - 4.3 ms`** per worker across 8 workers).
    - Two-copy `needsPrev` path (1 top part with `prev = 0` + 78 parts taking `needsPrev` + `png_part_finish`, the
      likely case for Scumble's 99% Paeth/Average files): inferred sum **`~66.0 ms`** across the 79 parts
      (**`~8.2 ms`** per worker across 8 workers).
- On a `4,096 x 256` part (`4,194,560` bytes of `lines`, `4,194,304` bytes of `out`), single-pass `copyIn` costs
  **`0.21 - 0.23 ms`** in Electron V8 (`0.16 - 0.19 ms` in Node V8), and two-copy `copyIn` (`needsPrev` + `finish`)
  costs **`0.43 ms`** in Electron V8 (`0.32 ms` in Node V8).
- The 65,536-byte CPU-canvas round-trip table `rt` stays resident in wasm memory via `this._resident(rt)` (`65,536 B`
  copied on the first call on each instance, `0 B` on every subsequent call).

3. Verification & Mutation Round (`docs/measurements/k7_2026-11-09/mutation/results.txt`)
-----------------------------------------------------------------------------------------
- `tools/px_test.js` (`pngPart` group under both Node and Electron, plus full suite):
  - `png_part_lines_cap` across widths `[-5, 0, 1..0x40000000]` including clamp boundaries `1024/1025` (2,048-row upper
    clamp from `programRows` / `bandPlan`), `6000` (349-row band part = `8,376,349 B`), `8192/8193`, `2097152/2097153`,
    and overflow `0x3fffffff/0x40000000`.
  - `160` `png_part_decode` + `48` `png_part_finish` `twinCheck` cases across 16 shapes (`1x1` up to `4097x2`), all 5
    first-row filters `0..4`, with and without `prev`, with CPU-canvas `rt`, custom `rt`, and `null` `rt`, and across
    opaque, single-translucent-pixel (`a = 254` at first/last pixel), and mixed-alpha inputs, with `shift: [0, 2, 3]`
    for decode and `shift: [0, 3, 4]` for finish passing the shifted views directly to the kernel.
  - Error codes `-4` (`PART_NOT_LINES`) and `-5` (`PART_BAD_FILTER`) on wrappers and raw wasm exports (`png_part_decode`,
    `png_part_finish`), verifying with `eqBytes` that every byte of `lines`, `prev` (`pJ`, `pP`), and `out` (`oJ`, `oP`)
    is untouched on every refusal, plus a 240-case seeded fuzz of `length`, `w`, `rows`, and filter bytes (including
    inputs bad in both length/dimensions and filter bytes, pinning `-4` before `-5`).
  - Multi-part PNG round-trip: `pngPart` -> `DecompressionStream("deflate-raw")` (with `03 00` appended to non-last parts
    only) -> out-of-order `pngPartDecode` -> forward `pngPartFinish` -> `adlerCombine` checked against `refAdler32` over
    the concatenated inflated scanlines + RGBA round-trip verification.
  - Node/runtime native `DecompressionStream("deflate-raw")` refusal check: verifies that the runtime's native stream
    rejects a 2-part raw deflate stream with a shared LZ77 window across `Z_SYNC_FLUSH` (distance before part 1's start),
    corrupt deflate bytes, and truncated streams (note: this is a Node/runtime check of the native stream and reaches no
    K7 wasm code when `DecompressionStream` throws; Electron worker tests on Chromium's `DecompressionStream` are part of
    K8).
  - Resident `rt` table check (`65,536 B` copied on first call, `0 B` on second call) and `kernels.js` switching.
- `tools/mutation_round.py` (`docs/measurements/k7_2026-11-09/mutation/mutants_k7.py`): `20` mutants across
  `crates/px/src/png.rs`, `renderer/editor/px/kernels_js.js`, and `renderer/editor/px/px.js` (including
  `cap_clamp_max_2047`, `js_filter_check_after_unfilter`, and `px_decode_ignore_byte_offset`) ->

- `tools/run_gates.sh` (`SCUMBLE_CDP_PORT=9621`, `--offline`):
