1. What the copy of `lines` into wasm memory (`copyIn`) costs
-------------------------------------------------------------
Because `DecompressionStream("deflate-raw")` delivers the inflated `lines` as a JS `Uint8Array`, `px.pngPartDecode`
copies `lines` (`rows * (1 + 4 * w)` bytes) into wasm memory before `png_part_decode` runs:
- On a standard `8 MB` part of a `15,000`-wide RGBA8 layer (`15,000 x 139`, `8,340,139` bytes of `lines`, `8,340,000`
  bytes of `out`), `copyIn` costs:
  - **Electron 44.2.0 (V8 15.2)**: **`0.43 - 0.47 ms`** per part (`0.052 - 0.056 ms/MB`, `17.7 - 19.4 GB/s`), which is
    **`3.3% - 4.2%`** of the `10.67 - 13.35 ms` `pngPartDecode` call.
  - **Node 24.18.0 (V8 13.6)**: **`0.43 - 0.53 ms`** per part (`0.052 - 0.064 ms/MB`, `15.7 - 19.4 GB/s`), which is
    **`3.1% - 4.4%`** of the `11.69 - 14.34 ms` `pngPartDecode` call.
  - Across all `72` parts of a `15,000 x 10,000` layer (`600.01 MB` of `lines`), the single-copy `copyIn` sum across the
    worker pool is **`~32.4 ms`** (`~4.1 ms` per worker across 8 workers).
  - When a part's `prev` is not yet available (`prev == null` and `firstFilter >= 2`, `needsPrev: true`), `lines` is
    copied in once during `png_part_decode` (for the whole-line check, filter check, and Adler-32: `3.08 ms` total in
    Electron V8) and once during `png_part_finish` (`2 x copyIn = 0.91 ms` in Electron V8, `0.82 ms` in Node V8).
- On a `4,096 x 256` part (`4,194,560` bytes of `lines`, `4,194,304` bytes of `out`), `copyIn` costs **`0.21 - 0.23 ms`**
  in Electron V8 (`0.16 - 0.19 ms` in Node V8).
- The 65,536-byte CPU-canvas round-trip table `rt` stays resident in wasm memory via `this._resident(rt)` (`65,536 B`
  copied on the first call on each instance, `0 B` on every subsequent call).

    `2097152/2097153` and overflow `0x3fffffff/0x40000000`.

    offset).

    `png_part_finish`).

    only) -> out-of-order `pngPartDecode` -> forward `pngPartFinish` -> `adlerCombine` + round-trip verification.
