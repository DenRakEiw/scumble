  What it says: the window's block before the reader is gone on every file and both routes (PSD 1,833 -> 0 ms, TIFF
  487 -> 0, PNG 429 -> 0); the longest block of a PSD open is now the drop's (1,833 -> 619 ms: what is left is the
  reader's own, D0's band writes and the shader link). The transfer is now a wait, not a block: the fetch streams about
  700 MB/s through the scheme (1.4 s for 925 MB), so a Ctrl+O PSD open still lands about 1.5 s after a drop of the
  same file (6.9 s against 5.4 s; before 7.7 s). A drop from Explorer pays no read at all, before or after (transfer 0:
  a disk-backed File is read by the readers as they slice it). The drop rows moved between the two sessions (PSD
  4.7 -> 5.4 s) with the same code: the machine's state, so compare routes within one table.
