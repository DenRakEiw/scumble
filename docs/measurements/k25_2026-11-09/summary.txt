K25 measurement summary (2026-11-09)
====================================

Behaviour change: Layered exports (PSD, ORA, `fillLayerCanvas`, `fillLayerRows`) containing a depth-limited fill layer
now snap the fill layer's alpha to `map.guide` (the base picture's guide colours) instead of the fill layer's own
colours when edge snap is enabled, changing exported fill-layer alpha bytes toward the screen's `limitStage`.

Scope (docs/PLAN_WASM_BUILD.md §4.8 K25):
- `limit_alpha_rows` in `crates/px/src/range.rs` (SIMD128 `f64x2` + scalar, sharing `range_weight_f64x2`, `snap_field`,
  `u16_bilinear`, `range_weight`, and `js_round_byte`), exported from `crates/px/src/lib.rs` (ABI 37), wrapped in
  `renderer/editor/px/px.js` (`Px.limitAlphaRows`, chunking into at most 256 rows per wasm call and copying only that
  chunk's `subRgba` (`<= 15.36 MB` at 15,000 x 256) and `[wy0..wy1]` row window of `map` and `guide`—clamping to the
  full `[0..mh - 1]` map height when extreme affine coefficients produce non-finite corner `ryMin`/`ryMax`—and setting
  `err.doneRows = cy` on a partial-chunk failure), JS twin in `renderer/editor/px/kernels_js.js` (`limitAlphaRows`,
  using `rangeSnapField` with `libmExp` so twin and both wasm builds match bit-for-bit across Node and Electron 44 V8
  15.2), routed in `renderer/editor/px/kernels.js` under `"limitAlphaRows"` (resuming from `err.doneRows` on a mid-call
  OOM/trap so completed chunks are not re-multiplied).
- `limitAlphaRows` in `renderer/editor/inpaint_limit.js` normalizes with `normalizeStoredLimit(limit)` (preserving
  `c17c6367` so a stored limit never throws on export), checks that `[lim.lo, lim.hi, lim.fLo, lim.fHi, sigmaR, tau]`
  and all 8 transformed band-corner coordinates are finite before calling `limitAlphaRowsKernel(rgba, map.data, map.w,
  map.h, m, x0, y0, w, h, lim, snap, gRaw, col)`, and otherwise falls back to the non-throwing JS loop. When `col` is
  null and `map.guide` is present, both the kernel and the fallback loop sample the snap reference colour from
  `map.guide` at `Math.floor(mx), Math.floor(my)` (clamped to `[0, mw - 1] x [0, mh - 1]`) instead of `rgba`'s own fill
  colour.
- `tools/px_jobs.py`: `fill_limit` `routeRan` asserts `win.limit_alpha_rows === row.bands` on `"rust"` and `0` on `"js"`,
  and `KERNEL["fill_limit"] = ["limit"]`.
- `tools/ab_median.py`: `ROUTE_EXPORTS["limitAlphaRows"] = ("limit_alpha_rows",)`.
- Route decision by measurement (§1.1, 3 runs with `--rounds 3` per `tools/ab_median.py`):
  - `--ab limitAlphaRows=js:rust` (`after/ab_r1..3.jsonl`): `verdict: rust` (`6213.3 ms` vs `10880.1 ms` wall, lower by
    `4666.9 ms` > spread `1447.3 ms`; kernel row `6092.4 ms` vs `10728.2 ms`).
  - Both `px_jobs.py`'s `fill_limit` job and `export_test.py --perf --fill-limit` measure the snapped path (`snap = 50`
    with `map.guide`); the plain bilinear path (`sigmaR === 0` or no `guide`) is covered by the same `"limitAlphaRows"`
    route and was measured at the kernel row in `PX_BENCH` (`105.26 ms` twin vs `88.56 ms` simd / `91.13 ms` scalar on a
    `15000 x 256` band, `1.19x`).
  `limitAlphaRows` stays on Rust (`DEFAULT_ROUTES` carries no entry for `limitAlphaRows`, documented above
  `DEFAULT_ROUTES` in `renderer/editor/px/kernels.js`).
