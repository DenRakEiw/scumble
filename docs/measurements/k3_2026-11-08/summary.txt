Scope (docs/PLAN_WASM_BUILD.md §4.3 K3, §5 row 15):
- `crates/px/src/png.rs`: compile-time `const CRC_TABLE: [[u32; 256]; 16]` (IEEE 802.3 reflected polynomial `0xEDB8_8320`,
  slice-by-16, zero external dependencies), `pub fn crc32(src: &[u8], start: u32) -> u32`, and
  `pub fn chunk_frame(buf: &mut [u8], data_len: usize, kind: u32) -> u32` (writes `data_len` BE to `buf[0..4]`, `kind` BE
  to `buf[4..8]`, `crc = crc32(&buf[4..8 + data_len], 0)` BE to `buf[8 + data_len..12 + data_len]`, returns `crc`).
- `crates/px/src/lib.rs`: bumped `px_abi_version()` to `32` (`32: crc32, png_chunk_frame`, renumbered to `34` when merged
  into `wasm-kernels` at `dceec4d2`); exported `crc32` (with null/zero-len guard returning `start`) and `png_chunk_frame`
  (with null guard returning `0`).
- `renderer/editor/px/px.wasm`: `225,516 bytes`, sha256 `af9167aeab2bc319` on `44495d21` (before: `208,177 bytes`, sha256
  `2208b82f6775478a`).
- `renderer/editor/px/px_scalar.wasm`: `184,788 bytes`, sha256 `b7cd2fd78ddfbcf3` on `44495d21` (before: `167,451 bytes`,
  sha256 `ac99651178ff1fd3`).
- `renderer/editor/px/kernels_js.js`: moved byte-wise `CRC_TABLE` and `crc32(bytes, start = 0)` here as the JS twin, plus
  `pngChunkFrame(buf, dataLen, kind)` twin.
- `renderer/editor/px/px.js`: bumped `PX_ABI` (`32` on `44495d21`, `34` on `dceec4d2`); added `crc32` and `pngChunkFrame`
  methods; updated `Px.prototype.pngPart` to allocate `po = a.take(cap + 12)`, deflate into `po + 8`, call
  `this.exports.png_chunk_frame(po, written, 0x49444154) >>> 0` (timed under `lap("chunk")`), copy out
  `chunk = this.u8().slice(po, po + written + 12)` once, set `bytes = chunk.subarray(8, 8 + written)`, and return
  `{ bytes, adler, raw: n, chunk, crc }`.
- `renderer/editor/px/kernels.js`: added `crc32: "kernelSize"` to `ROUTE_KINDS` and `crc32: 64` to `DEFAULT_ROUTES`
  (64 B is about a tie decided by the kernel row: `0.075-0.100 vs 0.028-0.074 us` at `16-48 B`, `0.093-0.138 vs 0.156-0.235 us`
  at `64-128 B` with JIT warm-up jitter in the JS column, `4.97x` at `64 KB`, and `4.26x` on `w0_bench crc32_64mb`).
- `renderer/editor/inpaint_png.js`: kept `export function crc32(bytes, crc = 0)` at line 30 routing through `kernels.js`;
  added `export function crc32Combine(crc1, crc2, len2)` (GF(2) matrix method via precomputed 32x32 operators `CRC_POW2`);
  updated `PngStreamWriter.finish()` to fold each worker part's `r.crc` via `crc32Combine(crc, r.crc >>> 0, c.byteLength - 8)`
  between its 4-byte length header and 4-byte CRC trailer, storing `this.crc = crc` and `blob.crc = crc`.
- `renderer/editor/inpaint_worker.js`: `pngPart(msg)` transfers `r.chunk.buffer` directly and returns `crc: r.crc` without
  calling `pngChunk("IDAT", r.bytes)` in JS.
- `renderer/editor/inpaint_bands.js`: `OraBandWriter._add(name, blob, crc)` takes the precomputed `crc` when available
  (`"mimetype"`, `"stack.xml"`, `layer` PNGs from `writePng`, and `mergedimage.png` from `writePng`), only dispatching a
  worker `"crc"` job when `crc === undefined` (`Thumbnails/thumbnail.png`).
- `renderer/editor/inpaint_export.js`: removed duplicate `CRC_TABLE` and `crc32`, importing `crc32` from `./inpaint_png.js`.

3. Unit & property checks (`tools/px_test.js` group `pngPart`)
--------------------------------------------------------------
- `crc32` and `png_chunk_frame` tested on both builds (`rust simd`, `rust scalar`) against `js`:
  - Standard IEEE 802.3 vectors (`"" -> 0`, `"123456789" -> 0xCBF43926`) and null/zero-len continuation.
  - 303-case `twinCheck` for `crc32` across lengths `0..67`, `128..65537`, all 256 byte values in every slice-by-16 lane
    `0..15` and remainder, non-zero `start`, odd `byteOffset`, and cross-check against Node `zlib.crc32`.
  - Continuation across arbitrary splits (`0..257` bytes).
  - `crc32Combine` property checks across zero/negative lengths, powers of 2 up to 16 MB (`1 << 0` .. `1 << 24`, covering
    bits 0..24), `~7.7 MB` (`7,700,000` B, the size of a 15k part), and all split points `0..260`, checked against
    `zlib.crc32`.
  - 84-case `twinCheck` for `png_chunk_frame` against `pngChunk` and `js.pngChunkFrame`.
  - `inpaint_png.crc32` route cut-off check (`< 64` B stays in JS, `>= 64` B routes to Rust, `setRoute("crc32", "js")`
    forces JS).
  - `OraBandWriter` combined entry CRCs check: verifies `crcJobs === 1` (thumbnail only) and that all 5 ZIP entry local and
    central directory CRCs match `px.crc32(entryBytes)`.
