## 1. Skins

The shape is CLAUDE.md item 20: tokens first (about 25 to 30 CSS custom properties replacing the 89 hard-coded
colours of `renderer/shell.css`, `assistant.css`, `help.css` and the editor's `STYLE` string, canvas overlays reading
them through `getComputedStyle` once per theme change), **the default theme pixel-identical to today** (a screenshot
gate on both backends), then a skin as a plugin without JS (`plugin.json` with `"registers": ["skin"]`, a `skin.css`,
its own images and fonts), chosen in *Settings > Appearance*, switched live. Protected from skins: the assistant's ask
cards, the masked API keys, the selection outline's contrast.

**The two skins, names decided by the user:**

- **"90s"** - the look of a late-90s media player: bevelled grey-blue panels, a black LCD panel with green segment
  text, small pixel type, gradient title bars. Own artwork only: no Winamp logo, no original skin bitmaps, no "Winamp"
  in the name or the files. A pixel font only under the OFL (shipped in the skin folder; the CSP allows `'self'` only).
- **"Duck"** - after Pollen Robotics' / Hugging Face's Microduck robot: its palette from the press kit
  (https://pollen-robotics.com/microduck/press-kit/), soft rounded shapes. No robot artwork or logo unless the press
  kit's terms allow it; "Duck" is our name, not theirs.

The editor's `STYLE` lives in `renderer/editor/`, so the tokens reach the ComfyUI node too (with today's values as the
defaults): `build_node.py --check` and `nodecopy`.

**Built 2026-09-26**: `docs/SKINS.md`. The review of the build found that a skin could still paint over the assistant's
question (a `box-shadow` is not hit by `elementFromPoint`) or squeeze the chat after the one check (an animation
delay); since then the question draws itself in a shadow root and, while it is open, in the top layer
(`renderer/skins.js` `protectAsk`), and the check repeats four times a second while it is open (gate steps 11 and 13).

## 3. Documents and safety

- **An own document format** that reopens fully editable: filter layers, text, shapes, colour match, prompts, recipe,
  crop, selection and saved selections, references, masks. `getValue()` is already the document and the autosave
  bundle references mirror files (`renderer/editor/host.js` ~1434-1443). A zip container like ORA (the ORA writer
  runs in the pool, the reader exists) with a `scumble/` folder, **streamed through the pool** (a 15k document with
  several layers is gigabytes), written to a temporary file and renamed. File extension `.scumble` (the user may
  rename it). Save / Save As (Ctrl+S keeps saving the visible picture unless the user wants Ctrl+S for the document -
  to decide), the dirty marker, "close asks to save", recent files (`app.addRecentDocument` plus an own list),
  reopening a closed tab, opening a `.scumble` by double click (file association in the installer and the MSIX).
- **Quit safety:** today a quit or an update install skips the pixel flush (`saveBeforeRestart`, `renderer/shell.js`
  ~1861, is only called from the tiles restart button; layer pixels upload 15 s after the last change), so the last
  strokes can come back without their pixels. Prevent close and install, flush, then quit; a `render-process-gone`
  handler that reloads and restores; two or three autosave generations; gates that close right after a stroke and
  kill the renderer.
- **A history panel:** the undo steps as a list with human labels (about 50 `pushUndo` sites), named snapshots on
  `turnSnapshot()` / `restoreTurn()` (tiles only, capped in memory), a configurable undo depth.
- **TIFF open and save:** the Open dialog lists `tif` / `tiff` today and nothing decodes it. Reading 8 and 16 bit
  (16 reduced to 8 as PNG and PSD), writing 8-bit RGB(A) in bands with Adobe-Deflate strips (the PNG part writer's
  Rust deflate); a Rust crate or UTIF.js (MIT) in a pool worker.
- **Editable layer masks in PSD** (write the -2 user-mask channel and its record in both writers, read it back as a
  mask instead of multiplying it into alpha).
- **Metadata:** an export switch that leaves out the prompt, seed and recipe graph every PNG carries today; sRGB tags
  on exports; keep EXIF / IPTC / XMP from the source (Orientation reset to 1) - the full metadata part only as far as
  the design pass finds it cheap.

## 4. Brushes

- **Smudge, clone and heal at 15k:** read only the dab's or the source's box from the tiles (smudge draws from the
  whole-layer mirror today: 0.4 to 0.75 s per move at 15k in the 0.1.13 numbers, to re-measure first; clone and heal
  flatten the whole picture at the press), no "Base copy" layer on the base.
- **A pro smudge:** a carry-buffer engine as a Rust kernel on tile bytes (smearing with alpha, strength and length),
  sample *layer / current and below / all layers* (the seam of a result layer can pull in the base), finger painting,
  pressure to strength, imported tips and spacing.
- **Clone:** a source overlay, rotate / scale / flip of the source, tips.
- **Flow** (build-up within a stroke), pressure curves with coalesced pen events, a stroke stabiliser.
- **The 400 px brush size cap raised** for 15k (measure the dab cost first).
- **Frequency separation** as an action (a blurred low layer, a high layer in linear light) - which brings the
  **linear light** blend mode forward from item 22's release 4 (GL compositor, Rust kernel and ABI bump, the Canvas 2D
  emulation, PSD / ORA maps and the reader).
- **Dodge and burn:** a one-click dodge-and-burn layer (50 % grey, soft light), then real dodge / burn / sponge brushes
  on the new regional path.
- A gate step for every tool (none has one for smudge or heal today).

## 5. Repair, remove, liquify

- **A healing brush with a gradient-domain (Poisson) blend:** a solver in `crates/px` with its bit-exact JS twin, run
  per stroke over the stroke's box in a pool worker; the preview-equals-commit rule of the live-stroke gate needs an
  explicit "healing" step at release or an approximate preview.
- **Remove / spot heal:** an in-app inpainting model on ONNX Runtime beside SAM2 and BiRefNet - Big-LaMa's ONNX port
  (Apache-2.0, 512 x 512 input; licence to confirm before shipping; MI-GAN is out, its weights' licence is disputed) -
  cropped, scaled and stitched through `stitch.js`; free, offline, instant for small spots. Possibly also an in-app
  provider variant so "fill the selection by content" is Generate with that recipe.
- **Patch tool and content-aware move** on the same solver.
- **Liquify:** push / grow / shrink / swirl / restore, a freeze mask. `docs/PLAN_0_1_7.md` §4 has a design from before
  the tile engine; at 15k it needs a finer local displacement field over the touched region, a way for the base (a copy
  or result layers only), and a bake in bands through the pool.

## 6. Layers pro

- **Multi-selection of layers** (Shift / Ctrl click, move and transform together, merge selected) - the prerequisite
  for groups - with **align and distribute** (to the selection box too).
- **Clipping:** a layer clipped to the one below; "a filter on this layer only" is `mix(in, filtered, baseAlpha)`,
  the same post-stage item 22's *Limit by depth* will use, so build it reusable. GL, Rust `composite_tile` (ABI, JS
  twin), `stackPlan` / program, Canvas 2D, the PSD clipping flag both ways, commands, the node build.
- **Layer mask operations:** invert, disable, reveal all / hide all, and a mask command over MCP (these are daily
  work here; the rest of the masks package waits in item 22).
- **Groups:** folders first (visibility, collapse, lock, move together, PSD `lsct` both ways) - 3 to 5 d; isolated
  groups with their own opacity and blend need a nested composite in every path - 7 to 9 d more.
- **Fill layers** (colour, gradient) as a reach-0 filter type - cheap, if it fits.
