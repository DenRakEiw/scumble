## Must fix before R1-S5 builds on it

1. **Magic wand selects nothing on the tiles backend** (`renderer/editor/inpaint_raster.js:508`, F4b). `tilesSource`'s
   `t.data` branch indexes `t.data` directly, but the worker transfers the wand's tiles as `ArrayBuffer`s
   (`inpaint_worker.js:589` and `:692`, `data: out.buffer`); the old `applyTilesToSelection` wrapped them in
   `new Uint8ClampedArray(t.data)`. Indexing an ArrayBuffer gives `undefined`, so every byte lands as 0: replace clears
   the selection, add / subtract / intersect do nothing. The `selection` gate passes synthetic `alpha:` tiles and cannot
   see it; the `editor` gate's `wand_and_bucket_flood_a_region_not_the_image` on `--tiles on` should. Fix: accept an
   `ArrayBuffer` in `tilesSource` (wrap in `Uint8ClampedArray`); add a `selection` gate step with a real wand on tiles.
2. **Clipped layers vanish from `flattenToCanvas` when the clip base is a hidden filter layer**
   (`inpaint_canvas.js:7377` `passStores`, `:16725` `drawLayersInto`, F5). Both now skip the clipped layer when
   `clipTargetOf` was not drawn, while `glViewComposite` (`:16562`) and `stackPlan` (`:6743`) still use `clipBaseOf`
   (null for a filter base, drawn as is). Screen and tiles export show the layer, the canvas-backend export, runs,
   thumbnails and `pictureInput` drop it. The plan wanted the skip only under `skipFilters`; the walks must agree.
3. **Colour-match statistics cached without the `skipFilters` key** (`inpaint_canvas.js:17361` `matchStats`,
   `:17214` `_mcache`, F5, canvas backend only). `host.pictureInput` flattens with `skipFilters`; a colour-matched layer
   above a shown filter layer then caches filter-free statistics (keyed by `compositeVersion` only) that the next
   export or run reuses, and vice versa. Add `skipFilters` to the key or bypass the cache on that path.
4. **DPT model size wrong for mixed sides** (`renderer/editor/inpaint_depth.js:46`, same in `tools/depth_probe.py:30`,
   R1-S3a). The mixed branch picks the side by absolute pixel distance; DPT compares `|1 - 518/side|`. 300 x 1000 goes
   in as 518 x 1722 instead of 154 x 518 (11x the pixels, a different map than the Python reference). Rule:
   `scale = |1-518/W| < |1-518/H| ? 518/W : 518/H`. Add mixed-side cases to the self-test table.
5. **`sample_depth` runs the model as a read** (`renderer/commands.js:2005` `readOnly: true`,
   `electron/main/assistant/policy.js:17,45` READS and AUTO, R1-S3b). It calls `ensureDepthMap`: the model, a worker job
   of several hundred MB and a status-line rewrite under the assistant's read policy. The plan: a `depth_map` command
   (AUTO, its own step) and `sample_depth` as a pure read that errors "run depth_map first". `busy()` (`commands.js:57`)
   and `status.pending` (`:327`) do not know `depthPending`, so other commands run during the job.
6. **The stale check compares two different pictures** (`inpaint_canvas.js:11273` `depthFingerprint`, `:11293`
   `isDepthStale`, R1-S3b). The stored fingerprint comes from the filter-free model input, the live one from
   `this.thumb`, which carries filter layers and the selection tint. With any filter layer or selection the map is
   "stale" after every change, whatever changed; the fallback `flattenToCanvas` throws on a 15k tiles document (E5).
   Fingerprint both sides from the same filter-free source.
7. **Depth range min..max instead of the 0.5 / 99.5 percentiles** (`inpaint_canvas.js:~11160`, R1-S3b). The probe
   clips (`depth_probe.py:51`), the app does not; a few outliers compress the 16-bit range, and the app's maps are not
   the ones judged at the checkpoint. `disparityRange` is imported and unused (a lint warning).

## The structural one: R1-S3b was built before F5 and F8

The depth map is a plain `this.depth` on the editor, not an `ed.maps.depth` (F8): not undoable, does not follow crop /
rotate / resize (a rotate during a run leaves the old map stretched over the new canvas), `.scumble` and autosave keep
only metadata and the 64 x 64 thumb (`setValue` restores `u16: null`, every reopen recomputes). `host.depthInput`
(`host.js:3934`) re-implements `pictureInput` (F5) and adds a second switch name `noFilters` beside `skipFilters`
through `passStores`, `drawComposite`, `drawLayersInto`. When F8 lands, R1-S3b has to move onto it and `depthInput`
onto `pictureInput` before R1-S5a (select by range) reads the map.

  user's.
